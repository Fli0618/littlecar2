# 01 需求边界与系统架构

## 目标

冻结调参工具首版的目标、运行模式、通信资源和安全边界，避免固件、协议和 GUI 同时扩张。

## 当前事实

- 控制器运行在 STM32，`AdvanceMotion_Update()` 由 TIM6 每 20 ms 调用。
- USART1 为 115200、8N1，PA9/PA10 已用于该串口，当前已有 RX DMA。
- USART6 已绑定 Jetson 通信，不得把调参命令塞入 `comm_jetson`。
- 当前主流程包含阻塞式比赛任务，因此调参首版采用专用固件模式。

## 首版边界

允许调整：

- X/Y 共用的位置 PID：`Kp_pos`、`Ki_pos`、`Kd_pos`。
- yaw 独立的角度 PID：`Kp_yaw`、`Ki_yaw`、`Kd_yaw`。
- 受软件边界限制的任意位姿目标和测试速度。

明确不调整：

- ZDT 电机内部 PID。
- 视觉对准 P 参数。
- 机械臂参数和比赛业务流程。

## 运行模式

使用 `TUNER_ENABLE` 构建开关进入专用调参模式。该模式首次烧录后可长期在线修改参数和目标，不与比赛主流程并行运行。UART 接收回调只负责搬运字节，协议解析和业务动作放在调参前台循环中。

## 系统分层

```text
Windows 调参工具
    │ 透明串口 / USB 串口
    ▼
USART1 + comm_tuner
    ├── 命令解析、校验、响应
    ├── 参数请求和安全控制
    └── 遥测发送调度
    ▼
AdvanceMotion
    ├── 运行时 PID 参数
    ├── 20 ms 周期边界切换
    └── 调试快照
    ▼
底盘与传感器
```

## 依赖与前置条件

- 后续需要用户在 CubeMX 中为 USART1 配置 TX DMA，并确认 DMA、NVIC 和串口资源不冲突。
- 本任务不修改 `.ioc`、Keil 工程或 `Drivers/`。
- 上位机首版以 Windows 11、Python 3.9+ 和 `low_numpy` 环境为准。

## 异常处理

- 未启用 `TUNER_ENABLE` 时，不启动调参协议服务。
- USART1 初始化或 DMA 配置失败时进入现有错误处理，不继续接受调参命令。
- 调参模式不得绕过现有坐标边界、速度上限和物理急停要求。
