# 02 固件运行时参数与热切换

## 目标

把六个 PID 编译期宏改为可在线请求的运行时配置，并保证运动中切换时控制周期只能看到完整的新旧配置之一。

## 依赖

- 完成 [01-需求边界与系统架构](01-需求边界与系统架构.md)。
- 保留 `AdvanceMotion_Update()` 的 20 ms 调度方式。

## 数据结构与接口

在 `advance_motion.h/.c` 中定义 `AdvanceMotion_PidConfig_t`，包含六个 `float` 字段：

```c
typedef struct
{
    float kp_pos;
    float ki_pos;
    float kd_pos;
    float kp_yaw;
    float ki_yaw;
    float kd_yaw;
} AdvanceMotion_PidConfig_t;
```

文档冻结以下能力：

- `AdvanceMotion_GetPidConfig()`：读取当前已生效配置。
- `AdvanceMotion_RequestPidConfig()`：校验并提交完整配置组，返回请求结果和配置版本号。
- `AdvanceMotion_RestoreDefaultPid()`：提交默认配置，不直接逐字段写入控制器。
- 调试快照接口：返回当前配置版本、目标、实际值、误差、控制输出、实测速度、积分和饱和标志。

## 生效流程

```text
前台收到 SET_PID
    → 校验六个值和有限范围
    → 写入 pending 配置
    → 设置 pending_valid 和 revision
    → 下一次 AdvanceMotion_Update() 开始时整体替换
    → 清除积分、实测速度历史和无进展计时
```

pending 配置和有效标志的读写必须使用短临界区或等价的原子保护；不得在 UART 回调中执行完整业务更新。

## 参数约束

- 所有值必须通过 `isfinite()` 检查。
- 首版禁止 NaN、Inf 和负值。
- 文档应记录六个参数的工程上限，并在 STM32 侧再次校验，不能只信任 GUI。
- 参数切换只复位控制历史，不取消当前目标；目标取消由 STOP、失联保护或现有运动终态逻辑处理。

## 异常处理

- 参数非法时保持旧配置，返回明确错误码和字段定位信息。
- pending 已存在时，新请求覆盖前必须保留最新版本号，不能产生半更新状态。
- 配置切换期间不得在临界区内发送串口数据或调用底盘运动接口。

## 验收标准

- 不重新编译即可修改六个参数并读取到新值。
- 控制周期内不会混用新旧参数。
- 热切换后积分、速度历史和无进展计时已按约定复位。
- STM32 重启后恢复固件默认值，未写入 Flash。
