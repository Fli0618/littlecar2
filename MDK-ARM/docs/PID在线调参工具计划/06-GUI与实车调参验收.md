# 06 GUI 与实车调参验收

## 目标

在 CLI 和协议稳定后制作最小可用 GUI，并建立从悬空测试到实车联合运动的验收流程。

## GUI 首版功能

- 串口、波特率、连接状态和当前固件能力显示。
- 六个 PID 参数的读取、编辑、应用和恢复默认。
- X、Y、yaw、速度上限、超时和航向约束的任意位姿目标输入。
- 始终可见的 STOP 和连接异常提示。
- 位置、航向、误差、控制输出和实测速度曲线。
- 参数版本、应用时间、丢帧和心跳状态记录。

依赖使用 PySide6、pyqtgraph 和 pyserial。GUI 不直接实现协议规则，统一调用 `tools/pid_tuner/` 的客户端。

## 线程与缓存

- GUI 主线程只负责控件和绘图。
- 串口线程负责读取字节、协议解析和回调投递。
- 定时器每 30 至 50 ms 批量刷新曲线，不为每一帧直接触发 Qt 重绘。
- 默认保留最近 30 至 60 秒采样，开始新实验时可清空缓存但不删除已保存 CSV。

## 实车验收顺序

1. 无负载连接测试：GET/SET/RESTORE、CRC 和重连。
2. 悬空底盘：验证方向、STOP、心跳失联和速度归零。
3. 低速单轴：先验证 X，再验证 Y，再验证 yaw。
4. 低速组合：X+Y、X+yaw、Y+yaw。
5. 受控速度联合测试：确认参数版本、曲线和饱和标志。
6. 最后才进行比赛路径或高速度测试。

## 调参记录规范

- 每次实验先保存 JSON 参数方案。
- 曲线中标记参数应用、STOP、失联和目标切换事件。
- 记录测试环境、底盘状态、速度上限、目标、异常现象和最终结论。
- 复现结果优先使用同一参数文件和同一测试目标，不依赖口头记忆。

## 安全与异常

- 未连接、心跳超时、协议错误或固件返回 ERROR 时，禁用运动控制按钮并保留 STOP。
- 任何 GUI 控制都不能替代物理急停和现场人工监护。
- 超出软件边界的目标和速度在 GUI 侧提前拒绝，STM32 侧必须再次校验。

## 验收标准

- GUI 不阻塞，连接断开后能自动停止发送并明确提示。
- 参数修改在曲线上有事件标记，遥测数据可导出。
- 按顺序完成从无负载到联合实车测试，且每阶段有可追溯记录。
