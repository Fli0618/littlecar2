# 05 PC 核心工具与数据管理

## 目标

先完成无 GUI 的 Python 协议库和命令行工具，把 STM32、串口和协议问题与界面问题分离。

## 目录约定

后续代码放在项目根目录 `tools/pid_tuner/`，不放入 Jetson 比赛包，也不修改 `jetson/src.*` 导入约定。建议结构：

```text
tools/pid_tuner/
├── README.md
├── pyproject.toml
├── pid_tuner/
│   ├── protocol.py
│   ├── serial_client.py
│   ├── models.py
│   ├── storage.py
│   └── cli.py
└── tests/
```

## 模块职责

- `protocol.py`：帧编码、CRC、字节流解析、异常帧恢复。
- `serial_client.py`：串口生命周期、接收线程、序号、ACK 等待、重试和遥测回调。
- `models.py`：PID、目标、状态和遥测数据类型。
- `storage.py`：JSON 参数方案、CSV 采样记录和 C 默认值导出。
- `cli.py`：`ports`、`get-pid`、`set-pid`、`goto-pose`、`monitor`、`stop` 等命令。

## 数据管理

- 参数方案使用带名称、时间、固件版本和备注的 JSON 文件。
- 遥测数据使用 CSV 保存，至少包含 tick、参数版本、目标、实际值、误差、输出和实测速度。
- 导出的 C 默认值必须人工复核后再提交固件，工具不得自动修改 `Core/`。

## 测试策略

- 协议编解码、CRC、半帧、粘包、坏帧和未知命令使用纯单元测试。
- 串口客户端使用 fake transport，不依赖真实串口、相机、模型下载或小车。
- CLI 使用临时目录验证 JSON/CSV，不把缓存、日志和 `*.egg-info` 提交到 Git。

## 已实现 CLI

- 入口为 `pid-tuner`，提供 `ports`、`get-pid`、`set-pid`、`restore-pid`、`goto`、`monitor` 和 `profile` 子命令。
- `set-pid`、`restore-pid` 必须追加 `--apply` 才会向 STM32 写入；`goto` 必须完整提供目标、速度和超时，并在阻塞执行期间每 500 ms 刷新心跳。
- `goto --csv` 采集遥测，`monitor` 仅被动监听且不发送心跳。`profile` 方案保存在 `tools/pid_tuner/profiles/`，运行时 CSV 保存在 `logs/`；两者均不提交到 Git。

## 验收标准

- 不打开 GUI 即可连接串口、读写 PID、下发目标、监控遥测和 STOP。
- 串口断开能超时退出并释放资源，重复运行不会残留后台线程。
- 测试不依赖真实硬件，协议错误能被明确报告。
