# 下位机闭环与安全修复说明

## 1. 初始化与调度

初始化顺序为：`OPS_Init/WIT_Init`、`CarPose_Init`、`AdvanceWorld_Init`、`AdvanceControl_Init`、`AdvanceMotion_Init`、`drive_emm_Init`。OPS 位姿有效后，`AdvanceWorld_ResetOrigin()` 会自动建立原点。

TIM6 每 1 ms 直接调用唯一周期入口，主循环不再消费任务标志：

```text
1 ms: CommJetson_Update
10 ms: OPS_Update -> WIT_Update -> AdvanceWorld_Update
20 ms: drive_emm_Update -> 控制权判断 -> AdvanceMotion_Update
500 ms: 状态灯
1000 ms: world 原点重试
```

`AdvanceMotion_Update()`仅在控制权为 `WORLD` 且 `GotoPose` 为 `RUNNING` 时输出速度，周期由 `ADVANCE_MOTION_CONTROL_PERIOD_MS` 配置。每轮只读取一次由 `AdvanceWorld_Update()`生成的缓存位姿。

`App_RunTask()`只用于顺序调用 Blocking 高级接口。Blocking 等待循环只检查状态并执行 `__WFI()`；最外层 `while (1)`同样只执行 `__WFI()`。

## 2. 停止和控制权

急停、心跳超时、普通停止、取消目标和底盘失能都先取消活动目标点。急停与心跳超时使用 `Chassis_Stop()`；普通停止使用 `Chassis_SmoothStop()`。

`advance_control`以单一 `NONE/WORLD/VISUAL` 枚举维护控制权。`GotoPose`申请 `WORLD`，完成、失败、取消或超时后切换到 `NONE`并立即停车；`VISUAL`当前只保留调度分支。

## 3. GotoPose 到达条件

进入位置和航向容差后，控制器立即发送零速度，并从此时开始计时。只有在 `ADVANCE_MOTION_ARRIVE_HOLD_MS` 内持续满足容差，状态才变为 `ARRIVED`。离开容差会清除保持计时并恢复闭环控制。

目标输入由 `advance_motion.h` 的以下配置限制：

- `ADVANCE_MOTION_WORLD_X/Y_MIN/MAX_MM`：场地可达范围。
- `ADVANCE_MOTION_MAX_VMAX_MM_S`、`ADVANCE_MOTION_MAX_WMAX_DEG_S`：最大目标速度。
- `ADVANCE_MOTION_MAX_TIMEOUT_MS`：最长目标超时。

## 4. 坐标和传感器配置

统一约定为 `+X 向右`、`+Y 向前`、`+WZ 逆时针`。`Chassis_MoveMecanumEx()` 的第三参数已改为 `wz_ccw_rpm`，与物理速度接口的旋转符号一致。

在 `advance_world.h` 中完成 OPS/WIT 安装标定：轴交换、轴反向、航向偏角以及 OPS 到底盘旋转中心的 X/Y 偏移。修改这些参数后必须依次低速验证右移、前进、逆时针旋转和 world 速度方向。

OPS 接收层会拒绝 `NaN/Inf`、量程超限及位置突变帧。实际场地与最高速度变化后，应重新标定 `OPS_MAX_*` 门限。

## 5. 电机通信监督

`drive_emm` 为 USART3 提供 DMA 发送队列，发送帧在复制进队列后才清空多电机装载缓存。`drive_emm_Update()`在 TIM6 中推进反馈查询和超时检查；TX 超时通过 `HAL_UART_AbortTransmit_IT()`异步中止，并由 abort 完成回调恢复队列。

任何发送超时、队列错误、反馈超时、堵转或掉电标志都会使 `drive_emm_IsChassisFeedbackHealthy()` 返回失败。该反馈状态保留在驱动层和测试代码中，主循环不再设置额外的高层底盘反馈安全任务。

默认会向四个底盘驱动器写入 `DRIVE_EMM_HEARTBEAT_PROTECT_MS = 500 ms` 的心跳保护。该参数为持久化配置，上板前应确认驱动器为支持该命令的 Emm 固件；不支持时将 `DRIVE_EMM_ENABLE_HEARTBEAT_PROTECTION` 改为 `0`，并保留 STM32 侧反馈超时保护。

## 5.1 机械臂完全开环阻塞流程

机械臂不注册电机反馈、不维护软件零点，也不提供 `ARM_CONFIG`、`ARM_GET_STATUS` 或 `ARM_RESET_ZERO`。这些命令编号保留以兼容帧号，但均返回 `ACK_UNKNOWN_CMD`。

抓取和放置由 `AdvanceArm_Pick()`、`AdvanceArm_Place()` 同步执行。伸出、下降、夹爪、上升、收回五个原子动作均直接发送命令后 `HAL_Delay(1000U)`，单次 Pick/Place 约阻塞 5 秒。高层不检查命令发送结果、限位或任何反馈，因此 `ACK_OK` 不表示机械机构实际到位。

光电限位由 `sensor_limit` 统一读取，GPIO 配置仍由 CubeMX 的 `main.c` 负责。模块不注册 EXTI 回调、不做软件消抖，也不直接发送电机命令。当前引脚和逻辑映射如下：

| 传感器 | GPIO | 机械臂轴与方向 |
| --- | --- | --- |
| `SENSOR_LIMIT_LIFT_UP` | PC0 | 升降轴反向（上升） |
| `SENSOR_LIMIT_LIFT_DOWN` | PC1 | 升降轴正向（下降） |
| `SENSOR_LIMIT_SLIDE_FRONT` | PC2 | 滑台轴正向（前伸） |
| `SENSOR_LIMIT_SLIDE_REAR` | PC3 | 滑台轴反向（后收） |

`SENSOR_LIMIT_ACTIVE_LEVEL` 默认是 `GPIO_PIN_SET`。确认粉色线最终接法后，如需低电平有效，只修改 `sensor_limit.h` 中该配置即可。

`advance_arm` 当前不调用 `sensor_limit`。实车调试必须确认固定脉冲和 1000 ms 等待不会造成碰撞。

## 6. 串口与中断边界

USART1 只用于调试日志输出。USART6 使用 DMA + IDLE 接收 Jetson 帧，UART 回调只完成找帧、校验和结果缓存。

USART3 DMA/IDLE 回调调用 `drive_emm_OnUartRxEvent()`，TX 完成与异步 abort 完成分别释放发送状态。TIM6、UART 和 DMA 的 NVIC 优先级保持 CubeMX 现有配置。

## 7. 上板验收顺序

1. 断开负载或抬起车轮，确认四个电机 ID、方向和使能状态。
2. 确认 USART3 可收到 `0x35`、`0x36`、`0x37`、`0x3A` 回包，再允许底盘运动。
3. 低速验证车体右移、前进、逆时针旋转与坐标约定一致。
4. 静止等待 OPS 有效，检查自动原点建立。
5. 低速验证 `GotoPose(300, 0)`、`GotoPose(0, 300)`、到达后零速度和 `ARRIVED`。
6. 验证急停、取消目标、心跳超时和底盘反馈异常时的停车行为。
7. 在机械结构无碰撞风险的条件下，低速验证 Pick/Place 的固定顺序和约 5 秒阻塞时间。
8. 用逻辑分析仪或 GPIO 翻转测量确认 TIM6 中断与主循环调度不会超过 1 ms 基准周期。
