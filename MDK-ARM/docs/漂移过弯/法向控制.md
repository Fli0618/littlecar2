## 核心判断

你的判断只对一部分。小车向曲线外侧漂移，通常不是“参考点不够密”，而是：

> 当前控制器主要在车辆已经偏离后，通过横向 PD 把车拉回来；缺少对执行延迟和转弯法向加速度的提前补偿。

当前代码已经有：

* 路径投影和横向误差；
* 曲率前视；
* 基于 (v^2\kappa) 的曲线降速；
* 动态前视距离；
* 切向速度前馈；
* 横向 PD 修正。

但曲率目前主要用于**限制速度**，控制输出仍是“切向速度前馈 + 偏差出现后的法向修正”。因此在高速弯道中必然先向外漂，再被拉回。

---

# 一、当前实现为什么会向外漂

## 1. 曲率方向被丢失了

当前三点曲率计算最终使用：

```c
return AbsFloat(curvature);
```

它只保留曲率大小，不保留左转还是右转。

这足以计算：

```text
弯道速度上限
```

却无法生成：

```text
朝曲线内侧的法向前馈
```

所以控制器知道“前面有弯，需要减速”，但不知道“现在应提前向哪一侧施加多大的修正”。

应同时保存：

```c
signed_curvature_1_mm;      // 带方向，用于控制
curvature_abs_preview_1_mm; // 绝对值，用于速度规划
```

---

## 2. 横向 PD 是滞后的反馈

当前法向修正大致为：

```c
correction = kp * cross_track_error
           + kd * normal_velocity;
```

车辆只有已经偏离路径后，`cross_track_error` 才会增大。

弯道需要的法向加速度则应提前产生：

[
a_n=v^2\kappa
]

例如速度越高、半径越小，所需法向加速度越大。不能等偏差出现后再补偿。

---

## 3. 使用的是当前位姿，没有补偿系统延迟

实际控制链路存在：

```text
OPS测量
→ 串口接收
→ 世界位姿更新
→ 20 ms控制周期
→ STM32发送电机命令
→ 电机内部加速
→ 轮速建立
→ 底盘开始响应
```

控制器看到的位置，本质上已经是几十毫秒前的状态。弯道中这会产生明显的相位滞后。

动态前视距离只能部分缓解，它不是严格的执行器延迟补偿。

---

## 4. 速度方向发生变化，但没有二维加速度约束

当前只限制参考速度的大小：

```text
|v| ≤ reference_speed
```

但弯道需要不断改变速度向量方向。即使速度大小不变：

```text
(0, 600) → (200, 565)
```

也已经产生法向加速度。

目前没有对：

```text
Δvx / Δt
Δvy / Δt
```

进行显式限制和控制，因此理想速度方向可能比真实底盘变化得快，真实轨迹自然落在曲线外侧。

---

# 二、应采用“预测 Frenet 控制”

不建议直接上完整 MPC。STM32 端先实现一个轻量的预测控制器，已经能解决大部分问题。

## 1. 将离散参考点转换为连续路径

不能直接把稀疏折线当作真实轨迹。应在 PC 工具中完成：

```text
原始控制点
→ 分段三次 Bézier / 三次 Hermite 曲线
→ 按弧长均匀采样
→ 计算切向量、法向量、带符号曲率
```

建议采样间距初期使用：

```text
10～20 mm
```

关键要求是：

* 相邻点间距基本一致；
* 切线连续；
* 曲率尽量连续；
* 不允许相邻线段突然折转。

普通采样点只是曲线描述，不应要求小车逐点“命中”。要求每个采样点都精确经过，会造成控制振荡。

---

## 2. 预测车辆未来状态

设总等效延迟为 (\tau)，使用当前实测速度预测未来位置：

[
\hat{\mathbf p}(t+\tau)
=======================

\mathbf p(t)
+
\mathbf v(t)\tau
+
\frac12\mathbf a(t)\tau^2
]

航向同样预测：

[
\hat\psi(t+\tau)=\psi(t)+\omega(t)\tau
]

然后将**预测位置**投影到路径，而不是将当前 OPS 位置投影到路径。

伪代码：

```c
pred_x = pose_x + measured_vx * tau
                  + 0.5f * measured_ax * tau * tau;

pred_y = pose_y + measured_vy * tau
                  + 0.5f * measured_ay * tau * tau;

pred_yaw = yaw + measured_wz * tau;
```

初期没有可靠加速度时，可以先只用：

```c
pred_x = pose_x + measured_vx * tau;
pred_y = pose_y + measured_vy * tau;
```

---

## 3. 使用预测弧长选择前馈方向

获得预测位置对应的路径弧长 (s_p) 后，再计算：

[
s_{\text{cmd}}
==============

s_p+v_{\text{ref}}\tau
]

即根据车辆在执行器真正响应时会到达的位置，提前选择未来路径切线。

```c
delay_advance_mm = reference_speed_mm_s * actuator_delay_s;
command_s_mm = predicted_progress_mm + delay_advance_mm;
```

这会使车辆在进入弯道前提前改变速度方向，而不是进入弯道后才纠偏。

注意要将：

```text
几何前视距离
执行延迟补偿距离
```

分开处理。两者含义不同，不能继续共用一个 `lookahead_mm`。

---

# 三、增加曲率法向前馈

对路径点 (s_{\text{cmd}})，取得：

```text
单位切向量 t
单位法向量 n
带符号曲率 κ
```

计算所需法向加速度：

[
a_{n,\mathrm{ff}}
=================

v_{\mathrm{ref}}^2\kappa
]

再叠加预测横向误差反馈：

[
a_n
===

## v_{\mathrm{ref}}^2\kappa

## K_p e_n

K_d \dot e_n
]

其中：

* (e_n)：预测位置到路径的法向误差；
* (\dot e_n)：实测速度在法向上的分量；
* (\kappa)：带符号曲率。

然后构造世界坐标加速度：

[
\mathbf a_{\mathrm{cmd}}
========================

a_t\mathbf t+a_n\mathbf n
]

最后积分得到下一周期速度命令：

[
\mathbf v_{\mathrm{cmd},k+1}
============================

\mathbf v_{\mathrm{cmd},k}
+
\mathbf a_{\mathrm{cmd}}\Delta t
]

对应伪代码：

```c
a_normal_ff = reference_speed * reference_speed * signed_curvature;

a_normal = a_normal_ff
         - kp_cross_track * predicted_cross_track
         - kd_normal_velocity * measured_normal_velocity;

a_tangent = Clamp(
    (target_speed - command_tangent_speed) / dt,
    -max_decel,
    max_accel);

ax_cmd = tangent_x * a_tangent + normal_x * a_normal;
ay_cmd = tangent_y * a_tangent + normal_y * a_normal;

command_vx += ax_cmd * dt;
command_vy += ay_cmd * dt;
```

这才是真正意义上的：

```text
提前产生向内侧的运动趋势
```

而不是简单调大横向 `KP`。

# 四、速度规划必须使用真实底盘能力

当前有：

```c
ADVANCE_MOTION_PATH_MAX_LATERAL_ACC_MM_S2 = 600.0f
```

代码利用该参数按曲率降速。

但这个值如果高于实际底盘能力，速度规划会认为小车能够完成转弯，实机却会外漂。

麦克纳姆底盘的能力通常具有方向差异：

```text
前后加速度能力 ≠ 左右加速度能力
```

因此应从单一标量改成至少：

```c
#define PATH_MAX_FORWARD_ACC_MM_S2
#define PATH_MAX_LATERAL_ACC_MM_S2
#define PATH_MAX_DECEL_MM_S2
#define PATH_MAX_ANGULAR_ACC_DEG_S2
```

进一步可以使用加速度椭圆：

[
\left(\frac{a_x}{a_{x,\max}}\right)^2+
\left(\frac{a_y}{a_{y,\max}}\right)^2
\leq 1
]

速度上限仍按：

[
v_{\max}
========

\sqrt{\frac{a_{n,\max}}{|\kappa|}}
]

计算，但 `a_n_max` 应根据当前法向在车体坐标中的方向动态计算。

# 五、建立简单的电机响应模型

不需要一开始建立复杂动力学模型。先使用一阶模型：

[
\dot{\mathbf v}
===============

\frac{\mathbf v_{\mathrm{cmd}}-\mathbf v}{T_v}
]

离散形式：

```c
pred_vx += dt / tau_vx * (cmd_vx - pred_vx);
pred_vy += dt / tau_vy * (cmd_vy - pred_vy);

pred_x += pred_vx * dt;
pred_y += pred_vy * dt;
```

其中：

```text
tau_vx：前后速度响应时间常数
tau_vy：横向速度响应时间常数
```

通过实机阶跃实验标定：

1. 分别发送固定 X、Y 方向速度；
2. 记录命令速度和 OPS 实测速度；
3. 计算命令变化到实测速度开始响应的延迟；
4. 计算达到最终速度 63% 所需时间；
5. 分别得到 X/Y 方向的增益和时间常数。

之后可以在 STM32 每周期预测未来 5～10 步轨迹：

```text
预测周期 20 ms
预测长度 5～10 步
总预测时间 100～200 ms
```

计算量对 STM32F407 可控。

# 六、固定赛道可以增加迭代学习补偿

你们的路径是预先规划并反复调试的，这非常适合迭代学习控制 ILC。

每次运行后，按路径弧长记录：

```text
s
reference_x/y
actual_x/y
cross_track_error
reference_speed
signed_curvature
command_vx/vy
```

下一次运行时更新法向前馈：

[
a_{n,\mathrm{ff}}^{j+1}(s)
==========================

## a_{n,\mathrm{ff}}^j(s)

\gamma e_n^j(s)
]

这样同一弯道如果每次都向外偏 30 mm，下一轮会在进入该弯道前自动增加向内补偿。

但顺序必须是：

```text
先修正预测控制和速度可行性
→ 再使用 ILC 消除可重复误差
```

不能直接把规划路径整体向内偏移来掩盖控制器问题。

---

# 推荐实施顺序

第一阶段直接修改当前控制器：

1. 保留带符号曲率；
2. 增加等效延迟 `tau_s`；
3. 使用预测位姿计算路径投影；
4. 使用 (s+v\tau) 处的切线和曲率；
5. 增加 (v^2\kappa) 法向前馈；
6. 对世界速度向量增加二维加速度限制。

第二阶段进行实机辨识：

```text
X/Y方向速度响应
控制链路延迟
最大横向加速度
不同速度和半径下的外漂误差
```

第三阶段再增加按弧长存储的 ILC 前馈表。

这套方案比继续增加参考点密度或单纯调大横向 `KP` 更有效。当前最关键的问题是**缺少带符号曲率前馈和执行延迟预测**。
