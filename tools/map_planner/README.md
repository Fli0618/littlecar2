# 比赛地图路径规划工具

## v7 流程编辑

方案仅使用有序 `steps` 保存到点停靠、原地转向和连续路径段，不再提供全局规划模式，也不再加载 v5/v6 方案。
连续段的第一个点是随前序步骤自动同步的锁定入口点；中间点是软途经点，最后一个点是最终停车点。代码生成按流程顺序输出 GOTO、转向和 `AdvanceMotion_FollowPathBlocking`。

独立的 PySide6 赛前规划与仿真工具，不连接串口，也不会向小车下发指令。

## 垫步路径编辑

“新增垫步路径”进入逐点编辑模式：地图点击依次添加节点，最后一个节点显示为 `End`；`Enter` 在至少两个节点且编译校验通过时保存，`Esc` 放弃草稿，`Backspace` 删除最后一个节点。选中既有垫步路径后可通过“继续编辑垫步”追加节点。属性面板可调整垫步距离。

画布以两层显示垫步路径：下层为编译展开后的连续轨迹和辅助点，上层为用户定义的折线节点。辅助点及 A/C/B 转角相关标记均不可交互。`selected_step_path_points()` 对当前垫步路径返回经过严格编译校验后的路径点；无效草稿不会写入方案。

## 工作台实机执行接入

编辑器提供“实机运动”开关、单步执行、连贯执行和停止控件；控件只发射
`hardware_enabled_changed(bool)`、`single_step_requested(int)`、`continuous_requested(int)`、
`execution_stop_requested()` 信号，串口和运动编排由外部工作台负责。关闭开关时三个
执行按钮均禁用。

实机执行区通过 `runtime_axis_transform_changed(bool, bool, bool)` 报告 X/Y 交换、X 反转和 Y 反转选择。编辑器本身不改写方案；MotionWorkbench 同时将该选择用于实测显示和下发坐标转换。三个坐标变换开关每次启动均默认关闭。自定义起点的位置选择阶段会显示带方向的车体轮廓，越界或碰撞时显示为红色。

工作台可用 `set_execution_target()`、`set_execution_actual_pose()`、`set_execution_error()`、
`set_execution_trace()` 或 `update_execution_telemetry()` 注入目标、实际车辆、误差和轨迹。
遥测更新仅替换 `runtime_*` 图元，不会清空或重绘整个地图场景。

地图按官方 `2400 mm × 2400 mm` 图纸绘制。四个黄色区的定位坐标由“场地中心对称、十字通道居中”关系推导为 `(550,550)`、`(1400,550)`、`(550,1400)`、`(1400,1400)`。新建方案必须先选择启停区或自定义起点，再右击蓝色起点箭头设置朝向并确认。

- `选择`：框选，Ctrl 增减选择，`Ctrl+A` 全选节点，`Ctrl+Z` 撤销。
- `添加节点`：悬停时只显示目标点的透明小车和方向箭头，不计算或绘制车体扫掠面积；按住 Shift 吸附至相对前一动作位置的水平、垂直或 45 度方向，并显示虚线辅助轴。左键释放时才确认 GOTO，保存、播放和实机执行前仍会统一检查路径越界与碰撞。
- `障碍物`：左键按下立即添加直径 `50 mm` 的黑色圆形模拟障碍物；切换到选择工具后可拖拽。障碍物参与自动规划膨胀、路径扫掠和方案有效性判定。
- `自动规划`：以当前流程末端为起点，点击地图选择终点。红线表示场地边线、四个平台和黑色障碍物的物理禁碰轮廓；粉色表示按车体投影和安全距离生成的车体中心硬禁区；黄色表示允许进入但会提高 A* 代价的软膨胀区。可视图 A* 搜索任意角路径后，使用端点曲率连续的五次曲线并线、保留可调的末端直线对接段，再进行等距采样和整车扫掠复验。结果保存为普通 `continuous_path`，继续复用现有上传、保存和代码生成流程。默认开启“连续选择自动规划航点”，下一次点击会从上一航点继续规划；航点同时显示相对启停区 1 中心 `(2250,150)` 的图纸坐标差。
- 第二页提供类似 RViz 的“设置导航目标”：鼠标按下位置作为终点，拖动方向作为目标车头航向，松开后立即自动规划；界面显示当前航向参考线、大箭头、目标角度和航向差。规划器先生成保持当前航向的安全平移路径，仅在终点扫掠空间允许时追加目标转向。当前地图指针、所选航点和实车遥测位置会同时显示图纸/世界坐标。轨迹生成参数也位于第二页，低频使用的手动点到点、连续段、原地转向和曲线编辑仍收在“高级手动编辑”中。
- 中键拖拽或空格加左键平移地图；滚轮只缩放地图。
- 预览小车或已确认动作的小车预览可右击顺时针旋转 90 度；每个新 GOTO 都保存预览后的绝对世界航向。
- 动作序列可混排 `GOTO Pose` 与原地转向；原地转向保持当前位置不变，并转到绝对世界航向。可在左侧追加，或在当前动作后插入。
- 选中 GOTO 时可编辑位置、停留、线速度、角速度和航向约束；选中原地转向时仅编辑目标航向、最大角速度和超时。
- 框选或 `Ctrl+A` 后可批量平移、删除节点，`Ctrl+Z`/`Ctrl+Shift+Z` 撤销或重做。
- 第一页先设置车身长度和宽度，再设置场地边线、四个平台和随机障碍物各自的安全距离、软膨胀距离与代价权重。“安全距离”专指车身物理轮廓之外额外预留的间隙。粉色内框按车体尺寸基准叠加安全距离形成；黄色内侧带是软代价区。边线安全带会在启停区1/2、原料区、暂存区、粗加工区和二维码板对接口留出合法开口，物理外框始终不可越过。随机障碍物的放置、选择/拖动和删除集中在第一页顶部。

方案 JSON 使用 `map_version: 10`，通过有序 `steps` 保存动作，并在 `layout.costmap` 保存车身长宽以及三类安全距离、软膨胀距离和代价权重。旧方案缺少车身尺寸时默认按 `300 × 300 mm` 加载。v7～v9 方案加载时使用默认代价参数迁移；v5/v6 方案及旧 `mode`、`commands`、`path_points` 顶层结构不再加载。连续路径的播放仅用于几何预览和碰撞检查，不表示实车动力学或实际跟踪效果。

## 自动规划选型与边界

自动规划针对固定矩形场地采用可视图 A*，而不是在 STM32 上运行栅格 A*、TEB 或 MPC：固定平台顶点很少，可视图能直接得到任意角短路径，计算只发生在 Workbench，且不引入第三方数值依赖。场地边线、平台和随机障碍物分别配置安全距离、软膨胀距离与代价权重；随机障碍物还可配置物理半径。搜索层使用车身长宽中的较大半尺寸做保守圆盘膨胀：圆形障碍物保持同心圆，矩形平台形成直边加四分之一圆弧的圆角矩形；硬禁区与黄色软代价区使用同一几何。最终验证层再按配置的矩形车体、每个采样点的实际航向做完整扫掠。五次曲线的前三个和后三个控制点分别共线，使曲线与前后直线连接处的方向和曲率连续；最后一个拐点的平滑长度受“末端直线对接长度”限制。修改车身、代价或轨迹参数后，旧自动路径会标为过期，必须点击“重新规划全部自动航点”才能上传或生成代码。运行期间不重规划；STM32 只按 20 ms 周期跟踪已提交轨迹，偏离过大时停车并要求重新规划。

地图侧栏分为“代价地图”“点位与航点”“方案与输出”三页。第一页面向全局规划并说明 F407 局部跟踪职责；第二页默认只显示自动规划、连续航点、删除和重新规划，手动 GOTO、原地转向、连续段及贝塞尔工具收入默认折叠的“高级手动编辑”，曲线确认/取消只在曲线草稿期间出现；第三页管理方案、仿真、实机执行和代码生成。

Workbench 左侧控制栏、地图参数栏和右侧画布之间使用两级水平分割器；深色分割条可直接左右拖动，三栏均设置独立最小宽度。参数栏在窗口不足时显示横向滚动条，长说明自动换行，不再由右侧画布裁掉。

## 仿真模型

仿真不再演示 PID。直线移动以固定 `1000 mm/s²` 加速到动作线速度上限，并在剩余制动距离内以同一加速度减速至零；航向与原地转向以固定 `360 deg/s²` 加减速，并遵守动作角速度上限。

它没有车体质量、转动惯量、轮距或运动学、电机扭矩、轮胎打滑、电池、地面摩擦等实车参数辨识，因此只用于路径与动作时序预览，不能作为实车运动预测。

在项目根目录安装并启动：

```powershell
conda run -n low_numpy pip install -e tools/map_planner
conda run -n low_numpy littlecar-map-planner
```

离屏测试：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
conda run -n low_numpy python -m pytest tools/map_planner/tests -q
```

## 地图交互

- 起点标定时，右击蓝色起点箭头可重复顺时针旋转 90 度；点击“确认朝向”后才完成标定。
- `测距` 工具中，左键依次选择两个图纸点；第二点按住 Shift 可吸附至第一点的水平、垂直或 45 度方向。侧栏显示水平、垂直和欧式距离，并保留一条水平、一条垂直的地图全幅虚线作为路径对齐辅助。按 `Esc`、切换工具或开始下一次测距清除。
- 四个浅黄色 `450×450 mm` 平台是否禁行由“允许通过黄色区”控制；依据比赛规则，开关每次启动默认关闭（即黄色区禁止通过）且不写入方案。仅在离线调试时手动允许通过；场地边界始终有效。
- 原料区仅能沿上边缘 X=`1100～1300 mm` 调整，二维码板仅能沿右边缘 Y=`1100～1300 mm` 调整；除可拖动外，二者在比赛区域外的上方和右侧分别提供水平和垂直滑块，范围均为 1 mm 连续步进。二者均随方案布局保存。
- 暂停状态下右击小车外轮廓，可将当前节点航向顺时针旋转 90 度并启用航向约束。原地转向同样检查旋转扫过的完整车体面积，触及平台或越界时不可保存和播放。
- 动作编辑完成后会自动生成暂停时间轴，可直接拖动进度条定位到任意时刻；点击播放只负责从当前位置继续播放。
- 原料转盘按外径 300 mm、槽位分布圆直径 200 mm、120 度间隔和槽径 50 mm 绘制。

## 生成 STM32 业务函数

在方案操作区点击“生成业务函数”可打开代码预览窗口。方案必须完成起点与朝向标定，并至少包含一个动作；路径碰撞、越界和不支持的语义会被拒绝。

生成函数格式为 `void Task_<Name>(void)`，函数名称可在窗口内编辑并严格校验。生成器按步骤顺序为 GOTO 和原地转向调用 `AdvanceMotion_GotoPoseBlocking()`；每个连续路径步骤生成独立的 `static const AdvanceMotion_PathPoint_t` 数组并调用一次 `AdvanceMotion_FollowPathBlocking()`。GOTO 和原地转向使用 `CHASSIS_DEFAULT_ACC`，任一步骤失败都会取消运动；GOTO 的正数停留会转换为 `HAL_Delay()`。

`Waypoint.x_mm`、`Waypoint.y_mm` 和 `yaw_deg` 已经是根据起点定义的世界坐标，生成时不会再次进行坐标转换。原地转向保持上一个最近的 GOTO 目标位置。当前不支持 `use_yaw=False` 和 `stop=False`；节点的速度、角速度和超时使用 STM32 固件默认值，不会写入生成代码。

复制生成结果到能够包含 `advance_motion.h` 的 STM32 业务源文件中，并在调用前完成 `AdvanceWorld` 世界坐标原点建立。该功能只用于生成可复制的函数文本，不会自动修改 STM32 源文件、连接串口或模拟实时车辆运动。
